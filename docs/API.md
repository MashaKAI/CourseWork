# API

Базовий URL: `http://127.0.0.1:8000`. Усі запити й відповіді в JSON.
Інтерактивна документація (можна пробувати запити): `/docs`.

- `id` це рядок (hex).
- Час `created_at` це UTC у форматі ISO 8601 (`2026-10-17T12:00:00+00:00`). Показувати у локальній зоні має фронтенд.
- Помилка: HTTP-код і `{"detail": "текст помилки українською"}`.
  - `400` не пройшла валідація (порожнє повідомлення, зайнятий тег, немає прав на дію, невідомий учасник).
  - `401` немає токена, токен недійсний або невірний тег чи пароль.
  - `422` неправильна форма запиту (бракує поля).
  - `500` проблема зі сховищем (наприклад, пошкоджений файл даних).

## Автентифікація

Реєстрація й вхід повертають `token`. Усі інші запити (крім `GET /api/uploads/...`) мають заголовок
`Authorization: Bearer <token>`. Поточний користувач визначається за токеном, тому `sender_id` чи `user_id`
передавати не потрібно: видати себе за іншого неможливо.

| Метод і шлях | Тіло | Відповідь |
|---|---|---|
| `POST /api/users` | `{"username": "Артем", "tag": "artem_k", "password": "secret1", "password_repeat": "secret1"}` | `201` `{"id", "username", "tag", "token"}` |
| `POST /api/login` | `{"tag": "artem_k", "password": "secret1"}` | `200` `{"id", "username", "tag", "token"}` або `401` |
| `POST /api/logout` | | `204`, токен перестає діяти |
| `GET /api/me` | | `{"id", "username", "tag"}` |
| `GET /api/users` | | `[{"id", "username", "tag"}]` |

Ім'я: до 32 символів, літери/цифри/`.`/`_`/`-`, унікальне без урахування регістру.
Тег: 3-32 символи, латиниця/цифри/`_`, унікальний без урахування регістру (зберігається в нижньому регістрі, `@` на початку ігнорується).
Пароль: 6-128 символів, під час реєстрації передається двічі, інакше `400`. Зберігається лише солоний хеш scrypt.
Токен це випадковий рядок; на сервері зберігається тільки його SHA-256 хеш, тому сесії переживають перезапуск.
Невірний тег або пароль дає `401` з однаковим текстом.

## Розмови

| Метод і шлях | Тіло | Відповідь |
|---|---|---|
| `POST /api/conversations` | `{"participant_ids": ["id2"], "title": "необов'язково"}` | `201` `{"id", "title", "participants", "is_group", "admin_id"}` |
| `GET /api/conversations` | | розмови поточного користувача, кожна з `last_message` (або `null`) і `unread` (кількість непрочитаних) |
| `POST /api/conversations/{id}/read` | | `204`, позначає розмову прочитаною для поточного користувача |
| `PATCH /api/conversations/{id}` | `{"title": "Нова назва"}` | оновлена розмова; лише адмін групи; 1-64 символи |

Поточний користувач додається до учасників автоматично. Разом має бути мінімум 2 учасники; 3 і більше це група.
Особистий чат з тією самою людиною можна створити лише один раз (повтор це `400`), груп з тим самим складом може бути скільки завгодно.
Назву можна змінювати тільки в групі.

Непрочитані: це повідомлення інших людей, новіші за мітку прочитання користувача (мітка зберігається на сервері, тож лічильник однаковий на всіх пристроях). Власні повідомлення не рахуються. Для чатів, збережених до появи міток, усе вважається прочитаним.

## Повідомлення

| Метод і шлях | Тіло | Відповідь |
|---|---|---|
| `POST /api/conversations/{id}/messages` | `{"text": "привіт", "image_data": "data:image/png;base64,..."}` | `201` `{"id", "conversation_id", "sender_id", "text", "created_at", "image_url"}` |
| `GET /api/conversations/{id}/messages` | | масив повідомлень, відсортований за часом |

Текст: не порожній (якщо немає фото), до 2000 символів, пробіли по краях обрізаються. Читати й писати можуть лише учасники розмови.

### Фото

`image_data` це data URL у base64. Підтримуються PNG, JPEG, GIF, WEBP, до 5 МБ; тип перевіряється за вмістом файлу, а не за розширенням.
У відповіді є `image_url` (або `null`); файл віддає `GET /api/uploads/{name}`. Тег `<img>` не може надіслати заголовок, тому
ім'я файлу це випадковий 128-бітний ідентифікатор, який бачать лише учасники чату. Файли лежать у `uploads/` поруч із файлом даних.

## Пошук

`GET /api/search?q=привіт` повертає масив повідомлень (як вище) із розмов поточного користувача, що містять `q` без урахування регістру. Порожній `q` це `400`.

## Керування розмовою

| Метод і шлях | Що робить |
|---|---|
| `DELETE /api/conversations/{id}/messages` | `204`. Видаляє всі повідомлення й фото розмови в усіх учасників. |
| `DELETE /api/conversations/{id}` | `204`. Особистий чат видаляється повністю для обох. З групи користувач виходить. |
| `DELETE /api/conversations/{id}?everyone=true` | `204`. Адмін видаляє групу для всіх. |
| `POST /api/conversations/{id}/members` `{"user_ids": ["id"]}` | `201`, оновлена розмова. Адмін додає людей у наявну групу; нові учасники бачать усю історію, але вона не рахується для них непрочитаною. |
| `DELETE /api/conversations/{id}/members/{member_id}` | `204`. Адмін видаляє учасника групи. |
| `GET /api/blocks` | масив id користувачів, яких заблокував поточний користувач |
| `POST /api/blocks` `{"target_id"}` | `204`, блокування |
| `DELETE /api/blocks?target_id=<id>` | `204`, розблокування |

Якщо хтось із двох заблокував іншого, надсилання в їхній особистий чат дає `400`. До груп блокування не застосовується.

### Адміністратор групи

Створювач групи стає адміном (`admin_id`). Лише адмін може перейменовувати групу, додавати й видаляти учасників, видаляти всі повідомлення групи і видаляти групу для всіх
(у групі має лишитися хоча б 2 учасники, себе адмін видалити не може, лише вийти).
Будь-який учасник може вийти. Якщо виходить адмін, ним стає наступний учасник у списку. Інші на чужі дії отримують `400`.

## Дані

Зберігаються у файлі `data/messenger.db` (шлях можна змінити змінною середовища `MESSENGER_DATA`).
Файл створюється при першому запуску, запис атомарний (тимчасовий файл і `os.replace`).

## Старий демо-чат (WebSocket)

`/ws/{username}` це початковий демо-чат, який розсилає текстові рядки всім підключеним і не пов'язаний з історією вище.
Інтерфейс його не використовує: нові повідомлення підтягуються опитуванням раз на 2 секунди.
